# پارت ۲۰ — راهنمای ادیتور Rive
کد و هر دو خروجی واقعی آماده‌اند: `moments.riv` با حجم **18,100 بایت** و
`live-icon.riv` با حجم **26,800 بایت** در `public/rive/` ذخیره شده‌اند.
برای این نسخه **نیازی به ساخت دوباره یا خروجی تازه از ادیتور نیست**.
میزبان آرت‌بورد اصلی Live با نام دقیق `aniamtion` را انتخاب می‌کند؛
آرت‌بورد کمکی `font` دیگر باعث نمایش متن کمکی به‌جای دکمه نمی‌شود.
کپسول، قاب، تقویم و انیمیشن‌های Live حفظ شده‌اند.
راهنمای زیر برای ویرایش یا بازسازی بعدی است.
نتیجهٔ بررسی‌ها: [گزارش پذیرش نهایی](../reports/part20-live-acceptance.md).
شاخه: `codex/part-20-moments`. ادغام، انتشار، پارت ۲۱ و بررسی Opus انجام نشده‌اند.

## ۱. فایل مخصوص کلمات را بساز
در Rive یک فایل مستقل بساز و فقط یک Artboard با نام `Moments` داخل آن داشته باش.
اندازه دقیق: **390 × 340**. پس‌زمینه شفاف؛ بدون Fill پس‌زمینه.
آن را Artboard پیش‌فرض فایل قرار بده. هیچ عکس، پرچم، کارت یا صفحه اپ را کپی نکن.

## ۲. View Model و نمونه پیش‌فرض را بساز
در بخش Data یک View Model به نام `MomentsVM` و یک Instance به نام `Default` بساز.
نوع و حروف بزرگ/کوچک نام‌ها دقیقاً مطابق جدول باشند:

| نام | نوع | مقدار اولیه |
| --- | --- | --- |
| `kind` | String | `goal` |
| `color1` | Color | `#0055A4`، آلفا ۱۰۰٪ |
| `color2` | Color | `#EF4135`، آلفا ۱۰۰٪ |
| `play` | Trigger | بدون مقدار ثابت |
| `phase` | Number | `0` |

View Model را به Artboard وصل کن و Instance بالا را نمونه پیش‌فرض/صادرشونده قرار بده.
در Preview هم همین Instance را انتخاب کن.
اسکریپت از `context:viewModel()` می‌خواند: این پنج مورد ورودی State Machine نیستند.
نیازی به ایجاد ورودی همنام در State Machine یا اتصال تک‌تک به Script Input نیست.
اگر اسکریپت هیچ چیز رسم نمی‌کند، ابتدا اتصال Data Context آرت‌بورد را بررسی کن.

## ۳. Node Script را اضافه کن
در Assets، Script جدید از نوع **Node Script** بساز و نامش را `Moments` بگذار.
تمام محتوای `rive/moments.luau` را جایگزین کد نمونه کن؛ Compile/Save کن.
یک Node خالی داخل Artboard بساز و اسکریپت را به آن متصل کن
(یا اسکریپت Node را از Assets به Hierarchy همان Artboard اضافه کن).
فقط **یک نمونه** از اسکریپت در Hierarchy باشد.
Node باید در مختصات **X=0، Y=0**، مقیاس **1/1** و Rotation=0 باشد.
گروه والدِ جابه‌جاشده یا مقیاس‌خورده برایش نساز.
اسکریپت خودش مسیر حروف و فلر را می‌سازد؛ فونت خارجی لازم ندارد.
اجرای اولیه خالی است: تا Trigger شلیک نشود، کلمه نشان داده نمی‌شود.

## ۴. State Machine پیش‌فرض
یک State Machine به نام `Moments` بساز و آن را پیش‌فرض Artboard کن.
برای یک حالت Idle، یک Timeline خالی بساز، آن را در State Machine قرار بده و Entry را به آن وصل کن.
Timeline نباید Position، Scale، Opacity اسکریپت یا مقدار `phase` را انیمیت کند.
هیچ Auto-play Trigger یا Listener برای اجرای خودکار `play` اضافه نکن.
میزبان اولین State Machine فایل را انتخاب می‌کند؛ بهتر است فقط همین یکی وجود داشته باشد.
انیمیشن کلمه با ساعت داخلی Node اجرا می‌شود؛ Timeline حامل افکت نیست.

## ۵. آزمایش گل
Preview را با State Machine و Instance پیش‌فرض اجرا کن.
`kind = goal` و رنگ‌های جدول را تنظیم کن؛ سپس Trigger مربوط به **View Model** یعنی `play` را بزن.
باید کلمه **GOAAAL** دیده شود، نه GOAL چهارحرفی؛ این همان کلمه مرجع است.
حروف با ورود نرم/بزرگ فرود می‌آیند، سپس نور و glint دیده می‌شود.
ترتیب فاز: `0 → 1 → 2`.
از لحظه Trigger، فرود آخرین حرف در **0.854 ثانیه** و پایان افکت در **1.6772 ثانیه** است.
در 60fps، فازها نزدیک **0.867** و **1.683** مشاهده شدند.
پس از پایان، کلمه در حالت نهایی باقی می‌ماند؛ خودبه‌خود محو نمی‌شود.
محو و جابه‌جایی در اپ توسط DOM انجام می‌شود.

## ۶. آزمایش قرمز و اجرای مجدد
`kind = red` بگذار و دوباره `play` را بزن.
باید **RED CARD** با طیف قرمز مرجع دیده شود؛ شکل کارت و عکس بازیکن داخل فایل نیست.
قرمز از رنگ‌های ثابت مرجع استفاده می‌کند. تغییر `color1/color2` رنگ قرمز را عوض نمی‌کند.
هیچ تأخیر 0.42 ثانیه‌ای داخل اسکریپت نیست؛ میزبان قبلاً آن را اعمال می‌کند.
فرود آخرین حرف **1.12 ثانیه** بعد از Trigger است. فاز ۲ در advance بعدی می‌آید،
تا فاز ۱ و ۲ در یک notification ادغام نشوند.
در 60fps نزدیک **1.133** و **1.150** مشاهده شدند.
برای گل هم تأخیر 0.1 ثانیه‌ای دوباره اضافه نمی‌شود.

در میانه ورود و بعد از پایان دوباره `play` را بزن؛ ساعت و فاز باید به صفر برگردند.
۲۰ بار بین هر دو حالت جابه‌جا شو و رنگ تیم گل را هم تغییر بده.
رنگ‌ها فقط هنگام Trigger نمونه‌برداری می‌شوند؛ تغییرشان در میانه اجرا روی همان اجرا اثر نمی‌گذارد.
هیچ کلمه قدیمی، callback تکراری یا پرش سیاه نباید دیده شود.
با همان اندازه 390×340 بررسی کن که مسیر حروف و ورود نرم از اطراف بریده نشوند.
فاز ۱ قرمز فقط یک فریم نگه داشته می‌شود؛ برای دیدنش پخش را آهسته کن.

## ۷. خروجی کلمات
از Export، فایل **Rive runtime (.riv)** را با scripts فعال/همراه فایل خروجی بگیر.
خروجی ادیتور باید امضای معتبر اسکریپت داشته باشد؛ فایل unsigned تست CLI را وارد public نکن.
خروجی را روی checkout شاخه پارت ۲۰ در مسیر زیر قرار بده:

`public/rive/moments.riv`

بودجه محافظه‌کارانه: **حداکثر 150,000 بایت**.
فایل فقط همین Artboard، View Model، State Machine و Node Script را داشته باشد.
خروجی محلی تست با CLI حدود 20KB بود. خروجی امضاشدهٔ دریافت‌شدهٔ ادیتور **18,100 بایت** است
و در `public/rive/moments.riv` بدون تغییر بایت‌ها ذخیره شده است.

## ۸. خروجی مستقل Live icon
خروجی فعلی کل دکمهٔ متحرک را دارد؛ کپسول، قاب بیرونی و نشان تقویم را نگه دار.
در خروجی فعلی، Runtime ابعاد آرت‌بورد اصلی را **433 × 152** گزارش می‌کند.
قاب نمایشی میزبان با نسبت **443 / 152** و ارتفاع **38** پیکسل تنظیم شده و
Runtime به‌صورت تناسبی داخل آن رسم می‌کند. برای خروجی فعلی اندازه را تغییر نده.
State Machine موجود و Timelineهای حرکت حذف نشوند.
فایل Live مستقل از Moments صادر شود. نام آرت‌بورد اصلی در کد میزبان دقیقاً
`aniamtion` است؛ اگر آن را در ادیتور تغییر دادی، انتخاب آرت‌بورد در `LiveGraphic.tsx` هم باید تغییر کند.
آرت‌بورد کمکی `font` در فایل فعلی باقی مانده و به‌صورت صریح انتخاب نمی‌شود.

View Model و Instance پیش‌فرض به Artboard متصل باشند:

| نام | نوع | مقدار اولیه |
| --- | --- | --- |
| `islive` | Boolean | `false` |
| `count` | String | `0` |

شرط‌های State Machine از `islive` خوانده شوند. Text Run عدد نشان تقویم به `count` وصل شود.
این Property اضافه برای دکمهٔ کامل لازم است؛ میزبان قبلی شمارنده را در DOM می‌ساخت.
میزبان جدید کل دکمهٔ Rive را با همان نسبت ابعاد و ارتفاع ۳۸ پیکسل نمایش می‌دهد
و بعد از اتصال موفق، قاب و شمارندهٔ DOM را کنار می‌گذارد.

فونت فایل اولیه **240,164 بایت** و کل فایل اولیه **243,688 بایت** بود؛
خروجی نهایی اکنون **26,800 بایت** است و بودجه را رعایت می‌کند.
اگر بعدها متن یا رقم جدید اضافه کردی، مجموعهٔ گلیف‌ها را دوباره بررسی کن.
در Assets، گزینهٔ Include فونت را روی **Glyphs used** بگذار؛ با یک Artboard کمکی
که صادر نمی‌شود، حروف `Live 0123456789` را با همان فونت به مجموعهٔ لازم اضافه کن.
فونت Embedded بماند. راهنمای قدم‌به‌قدم: [LIVE-EXPORT-FIX.fa.md](LIVE-EXPORT-FIX.fa.md).

در Preview، `islive=false/true` و `count=0/3/12/99` را آزمایش کن.
خروجی نهایی در `public/rive/live-icon.riv` با بودجهٔ **حداکثر 60,000 بایت** قرار می‌گیرد.
خروجی اولیهٔ بزرگ فقط برای تست در `verification/rive/exports/live-icon.original.riv` نگهداری شده است.

## ۹. بعد از خروجی گرفتن
قدم بعدی تو: **همین شاخهٔ پارت ۲۰ را بگیر و اپ را اجرا کن**؛ خروجی تازه لازم نیست.
برای بررسی محلی و ساخت دوباره:

```powershell
npm ci
npm run check
npm run build
npx playwright test -c playwright.rive.config.ts
```

اندازه فایل‌ها را نیز می‌توان با این دستور دید:

```powershell
Get-Item public/rive/moments.riv, public/rive/live-icon.riv | Select-Object Name,Length
```

وضعیت بررسی فایل‌های واقعی، اندازه، JS/WASM heap و رفتار تب مخفی در گزارش خروجی‌ها ثبت شده است.
خروجی فعلی Live به‌صورت مستقل دریافت و در Runtime واقعی بررسی شده است.
عامل ادیتور Rive را مستقیماً کنترل نکرده؛ آزمایش مرورگر با بازبینی پروژهٔ قابل ویرایش در ادیتور متفاوت است.
بررسی Opus انجام نشده است.
زمان‌بندی داخل فایل در نسخه فعلی همان تنظیم پیش‌فرض مرجع است: Duration=0.7، Speed=1.
قرارداد پنج‌property فعلی، تنظیم زنده سرعت یا منحنی‌ها از پنل وب را به اسکریپت منتقل نمی‌کند.
